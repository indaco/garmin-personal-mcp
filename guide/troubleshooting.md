# Problems and solutions

| Problem                                                     | Solution                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| The server does not start                                   | Make sure that Node.js is version 22 or later: `node --version`.                                                                                                                                                                                                                                                                                                                                                         |
| Claude Desktop does not find `npx`                          | GUI apps do not read your shell profile. Use the absolute path of `npx` (`which npx`) as the `command`.                                                                                                                                                                                                                                                                                                                  |
| Changes have no effect                                      | The client keeps the old server process. Restart the client: a new Claude Code session, or quit and start Claude Desktop again.                                                                                                                                                                                                                                                                                          |
| `Token request failed: HTTP 401/403`                        | The key is incorrect, expired or revoked. The message gives the page where you create a new key, and where the server reads the key. In the key file, the next call uses the new key: you do not restart. `setup --force` tests a new key and saves it there. In `GARMIN_PERSONAL_API_KEY`, change your MCP client configuration and restart the client. The error also shows the Content-Type and the body from Garmin. |
| `Token request failed`, another status                      | The Garmin token service has a problem. The key is not the cause. Try again later.                                                                                                                                                                                                                                                                                                                                       |
| An endpoint answers 400                                     | A query parameter has a different name. Use `garminGet` with the correct query string.                                                                                                                                                                                                                                                                                                                                   |
| An update says that Garmin stopped answering, or `HTTP 429` | Garmin allows about 100 requests in a short time. The update stops asking and keeps what it has. Wait a few minutes and update again: it does not fetch again what it saved.                                                                                                                                                                                                                                             |
| `Settings need a page from the template`                    | This page has no `garmin-settings` block: the assistant designed it (`freeform`) with no settings. To keep settings, make a new page with `layout` = `preset`, or a new `freeform` page with `workouts` or `recoveryHistory`, which adds that block.                                                                                                                                                                     |
| `... too deeply nested to write back`                       | A person or a tool changed a block of the page file, and its value has too many levels. The server does not change the page. Correct the block that the message names, or ask for a new page from the template: `layout` = `preset`. The new page does not keep the languages or the custom widgets of a block that the server cannot write back.                                                                        |
| The automatic update did not run                            | Ask your assistant "when does my dashboard update?". If the reply says that the job is missing, set the schedule again. The reply also gives the last update and its errors. The computer must be on at that time: Linux skips a missed time. After a change of the Node.js version, set the schedule again. Each run writes a line to `~/.cache/garmin-personal-mcp/refresh.log`.                                       |
| `Save the API key in ... first`                             | The automatic update reads the key from the key file, not from your MCP client configuration. Run `npx -y @indaco/garmin-personal-mcp@latest setup` or save the key in the file that the message names (default `~/.config/garmin-mcp/api-key`), then ask again.                                                                                                                                                         |
| You need more details                                       | Run `npx -y @indaco/garmin-personal-mcp@latest info`: it shows the key file, the data folder and the logs (see [Commands](cli.md)). Read the server log: `~/.cache/garmin-personal-mcp/garmin-personal-mcp.log`. Claude Desktop also writes `~/.config/Claude/logs/mcp-server-garmin-personal.log` (Linux) or `~/Library/Logs/Claude/mcp-server-garmin-personal.log` (macOS).                                            |

## Test the key

`doctor` tests the key with a token request to Garmin, and tests the key file, the folders and the
schedule. It shows the result, never the key. It works on each system, and with the key from the key
file or from `GARMIN_PERSONAL_API_KEY`. See [doctor](cli.md#doctor).

```bash
npx -y @indaco/garmin-personal-mcp@latest doctor
```

## Test the server

The server must answer with one JSON line:

```bash
echo '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"t","version":"1"}}}' \
  | npx -y @indaco/garmin-personal-mcp@latest
```
